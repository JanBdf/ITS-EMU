# ITS-Board Emulator — notes for Claude Code

Emulator of the HAW Hamburg ITS-Board (STM32F429ZI Nucleo on the ITS carrier
with a 4" ILI9486 display) for the "Informationstechnische Systeme" course.
Rust workspace, edition 2024. Read `README.md` for what it does and `PLAN.md`
for architecture, validation and known deviations before changing models.

## Layout

- `crates/emu-core` — Cortex-M4F machine on a vendored, patched Unicorn
  (`vendor/`): NVIC, SysTick, cycle model (`timing.rs`), idle and delay-loop
  skipping (`machine/poll.rs`, `machine/delay.rs`), GDB server, debug port.
- `crates/stm32f429` — peripheral models (RCC, GPIO/EXTI, timers, USART, SPI,
  I2C, ADC/DAC, DMA, ...). `crates/itsboard` — the board: display, touch,
  LEDs, buttons, external devices, network, Pico plugin, `Simulator`.
- `apps/its-emu` (CLI) and `apps/its-emu-gui` (eframe/egui). `crates/rp2040`,
  `usbip`, `stlink` support the Pico device and the ST-LINK over USB/IP.
- `tests/fixtures/ac6/*.axf` — course firmware built by `tools/build-fixtures.sh`
  (needs the ARM toolchain, `tools/arm-env.sh`). `tests/hardware/*.txt` —
  measurements of the real board that `crates/itsboard/tests/hardware.rs`
  compares HwCheck (`tests/fixtures/ac6-src/HwCheck`) against.

## Rules

- The real board is the reference. Peripheral behaviour comes from the
  reference manual and from measurements in `tests/hardware/`; do not guess
  timings — note an unmeasured value as such in the code comment.
- A change for speed must not change behaviour: build the CLI before and
  after and run `tools/perf/same-cycles.sh BEFORE AFTER` (every fixture:
  same cycles, output and screenshot). `tools/perf/bench.sh` times fixtures;
  `--no-idle-skip` numbers vary ±10 % with code layout, compare `perf stat`
  instruction counts for small gains.
- Changes to the vendored Unicorn go into both the sources under
  `vendor/unicorn-engine-sys/` and `vendor/unicorn-engine-sys.patch`
  (regenerate the file's section with `diff -u` against the crates.io
  sources in `~/.cargo/registry`), and get a bullet in `vendor/README.md`.
- Before finishing: `cargo fmt --all`, `cargo clippy --release --workspace
  --all-targets` (CI uses `-D warnings`), `cargo test --release --workspace`.
  The hardware tests skip silently when the fixtures are missing.
- Branches: only `main` and `experimental` exist; work lands on
  `experimental`. Commit only when asked.
- GUI screenshots for docs and checks: `ITS_EMU_GUI_SCREENSHOT=out.png:4`
  (seconds) with `xvfb-run -a -s "-screen 0 1400x1050x24"`; `ITS_EMU_GUI_VIEW`
  picks a start view (lcd, see-through, pins, devices, help).
- The board drawing (`apps/its-emu-gui/assets/board-*.svg`) is generated by
  `tools/hw/boarddraw.py` from measurements of the photos in `hardware_img/`
  (not in git); positions of interactive spots live in `board.rs` constants
  that the script reads.

## Profiling

`perf record -e cycles:u` on `target/release/its-emu FIXTURE --seconds 6
--no-idle-skip` (needs the sandbox off). In busy code about half of the
time is the per-block hook (`emu_core::machine::block_hook`) and the
next-block lookup after indirect branches; the rest is the JIT.
